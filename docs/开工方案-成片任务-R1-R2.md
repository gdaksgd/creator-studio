## 2. R1 · 可追溯快赢

### 2.1 目标

让用户能：

- 只下载某一阶段的工件，不必每次导整包；
- 在 run 详情看到完整操作时间线：创建、检查、改素材、确认版权、复核、导出、归档、绑定发布。

### 2.2 功能需求

#### FR-R1-1 阶段工件单独下载

在 run 详情新增「阶段工件」卡：

| 工件 | 文件名 | 来源 |
|---|---|---|
| 脚本 | `script.md` | `buildRunPackFiles(run, mode)` |
| 分镜表 | `shotlist.csv` | 同上 |
| 素材清单 | `assets.csv` | 同上 |
| 检查结果 | `checks.json` | 同上 |
| 发布说明 | `publish.md` | 同上 |

- 每个文件一个下载按钮/链接。
- 不要求 run 已 ready；草稿/阻塞状态也可下载。
- 不包含 `README.md` / `manifest.json`（完整包才有）。
- 下载走浏览器 Blob，不发请求。
- CSV 保留 UTF-8 BOM。

实现建议：

- 在 `runPack.ts` 增加：
  ```ts
  export interface StageArtifact {
    id: string;
    label: string;
    fileName: string;
    mime: string;
    content: string;
  }
  export function buildStageArtifacts(run: ProductionRun): StageArtifact[];
  export function downloadStageArtifact(artifact: StageArtifact): void;
  ```
- 直接用 `buildRunPackFiles` 的结果过滤，不复制生成逻辑。
- UI 用 `Download` 图标 + 文件名 + 一个小说明。

验收：

- 5 个工件均可单独下载；
- 内容与 run 快照一致；
- 下载后刷新页面不影响 run；
- 不产生网络请求；
- 没有媒体文件。

#### FR-R1-2 运行事件时间线

数据：

```ts
export type RunEventType =
  | 'created'
  | 'checked'
  | 'asset_updated'
  | 'rights_confirmed'
  | 'rights_revoked'
  | 'review_approved'
  | 'review_revoked'
  | 'pack_exported'
  | 'archived'
  | 'note_updated'
  | 'publish_bound';

export interface RunEvent {
  id: string;
  type: RunEventType;
  at: number;
  actor: string;
  summary: string;
  meta?: Record<string, string | number | boolean | null>;
}
```

- `ProductionRun.events?: RunEvent[]`。
- 每个动作追加一条事件，最多保留 200 条（超过丢最旧，UI 标明“已截断”）。
- 事件只记摘要，不写完整脚本/台词/隐私。
- 事件时间线在详情页底部（或右栏下方），按时间倒序；最近 8 条默认显示，可展开。

事件矩阵：

| 动作 | 事件 type | summary 示例 | meta |
|---|---|---|---|
| 创建任务 | `created` | 创建任务并锁定脚本快照 | scriptId, pipeline |
| 预检/重新检查 | `checked` | 发布前检查：3 阻塞 / 1 提醒 / 6 通过 | block, warn, pass, platformError? |
| 修改素材 | `asset_updated` | 镜 2 素材状态改为已准备 | sceneNumber, fields |
| 确认版权 | `rights_confirmed` | 已确认素材版权/授权 | — |
| 取消版权 | `rights_revoked` | 已取消版权确认 | — |
| 复核通过 | `review_approved` | 复核通过 | reviewer, warnings |
| 撤销复核 | `review_revoked` | 撤销复核 | reviewer |
| 导出包 | `pack_exported` | 导出发布包 | mode, fileName, fileCount |
| 归档 | `archived` | 归档任务 | — |
| 备注保存 | `note_updated`（可选） | 更新任务备注 | — |
| 绑定发布 | `publish_bound` | 绑定发布记录 | platform, bvid |

实现建议：

- 在 `runService.ts` 增加：
  ```ts
  const MAX_RUN_EVENTS = 200;
  function appendRunEvents(run: ProductionRun, inputs: Array<Partial<RunEvent> & { type: RunEventType; summary: string }>, actor: string): RunEvent[];
  ```
- 所有写操作在 `applyRunState` 之后追加事件；不要覆盖已有事件。
- 给以下函数增加可选 `actor` 参数（默认 `本地用户`）：
  - `createRun`, `refreshRun`, `updateAssetSlot`, `setRightsConfirmed`, `saveReview`, `saveRunNotes`, `recordRunPack`, `archiveRun`, `bindRunPublish`（R2）
- UI 调用时传 `user?.username || '本地用户'`；`ProductionRunDetail` 已引入 `useAuthStore`。
- `events` 是可选字段，旧 run 读取时默认 `[]`；**不需要升 Dexie 版本**。

验收：

- 创建后至少有一条 `created`；
- 重新检查后新增 `checked`，且计数正确；
- 改素材/版权/复核/导出/归档均新增事件；
- 刷新后事件保留；
- 备份 v3 恢复后事件仍在；
- 事件不超过 200 条；不泄漏完整脚本。

## 3. R2 · 发布闭环

### 3.1 目标

在 run 详情里把成片任务和真实发布结果接起来：

- 选题已有发布记录时：显示真实播放/互动、预测 vs 实际偏差；
- 允许把本次 run 绑定到这条发布记录；
- 没有发布记录时：不显示假数字，给出去记录发布的入口。

### 3.2 数据

```ts
export interface RunPublishRef {
  topicId: string;
  platform: 'bilibili' | 'douyin';
  bvid?: string;
  url?: string;
  title?: string;
  publishedAt: number;
  boundAt: number;
}
```

- `ProductionRun.publishRef?: RunPublishRef`。
- 只存在本机 run 里，不改 `Topic.published`、不改云端表结构。
- 绑定/解绑追加事件 `publish_bound`（解绑可加 `publish_unbound`，非必须）。

### 3.3 绑定规则

- 只有在 `sourceTopic.published` 存在时才显示“绑定本次发布”。
- 平台必须一致：
  - run 是 B站，`published.platform` 是抖音 → 显示“发布记录平台不一致”，禁止绑定。
- 优先按 `bvid` 绑定；没有 bvid 时按 platform + publishedAt + title。
- 同一 topic 可能有多条 run：
  - 绑定前查同 topic、同 platform 的 run；
  - 如果已有其他 run 绑定同一个 bvid，提示“该发布记录已绑定到另一条任务”，允许用户确认后继续（不静默抢占）。
- 绑定后：
  - 卡片显示“已绑定本次任务” + 绑定时间 + bvid；
  - 可解绑/重新绑定，留事件。
- 解绑/重新绑定不影响 `Topic.published`。

### 3.4 校准展示

在 run 详情新增「发布回填与校准」卡：

- 有发布记录：
  - 实际：播放、点赞、投币、收藏、分享、评论、发布时间、BVID、取数时间、来源（auto/manual）。
  - 预测：`sourceTopic.prediction?.value ?? sourceTopic.estimatedViews`；显示来源（AI/人工）。
  - 偏差：`formatDeviation(predicted, published.views)`。
  - 明确口径：`实际播放来自 B站接口或人工填写；预测只用于校准，不是承诺。`
- 没有发布记录：
  - 空状态：`这个选题还没有发布记录。`
  - 链接：`/?publish=<topicId>`，跳到选题看板并自动打开“记录发布”弹窗。
- 没有预测值：
  - 显示“该选题没有数字化预测”，不计算偏差；不补 0。
- 发布记录平台与 run 不一致：
  - 显示真实数据，但标注“平台不一致，不能作为本任务的直接校准”；不显示绑定按钮。

### 3.5 深链：从 run 去记录发布

在 `TopicDashboard.tsx`：

- 读取 `useSearchParams`，支持 `?publish=<topicId>`。
- topics 加载后找到对应 topic，调用现有 `openPublish(topic)`。
- 打开后清除 query，避免刷新重复弹窗。
- StrictMode 下用 ref 防重复打开。
- 不改变现有发布流程/接口。

验收：

- 在 run 详情点“去记录发布”能打开对应选题的发布弹窗；
- 发布后回到 run 详情能看到真实数据（重新进入页面即可）；
- 不自动发布、不修改账号数据。

### 3.6 导出包

- `manifest.json` 自动包含 `run.publishRef`（run 已经在 manifest 里）。
- 可选：`README.md` 增加“发布绑定”一行（有则显示 bvid/platform，没有则省略）。
- 不把校准数据写进 `checks.json`（它不是预检项）。
- 绑定发布后不需要强制重新导出；发布数据不是包内容的一部分。

### 3.7 R2 验收

新增到 `tools/runs-e2e.mjs`：

- 演示 run 的源选题有 `published` 时：
  - 详情显示实际播放/互动和偏差；
  - 点击“绑定本次发布”后显示“已绑定”，刷新后仍在；
  - 事件时间线出现 `publish_bound`。
- 平台不一致的 fixture（可在纯函数/单测中覆盖）：不显示绑定按钮。
- 没有发布记录时：显示空状态和深链，不显示 0 或假数字。
- 深链 `/?publish=<topicId>` 打开对应发布弹窗（可用一个已发布 topic 验证）。

## 10. 已知坑

1. **后台服务会掉**：长时间不操作后 5173/3001 可能退出；验收前先 `curl` 健康检查。
2. **Edge 调试端口冲突**：`portal-check` 等固定端口的脚本可能连到旧 target；优先用 `runs-e2e` 的随机端口。不要为了跑测试杀用户正在用的 Edge。
3. **StrictMode 双执行**：详情页自动预检已用 promise 去重；事件追加要注意不要在 effect 双调用里重复写。写操作放在用户动作/service 内，不放在 render。
4. **旧 run 没有 events**：所有读取用 `run.events ?? []`；写入时保留旧数组。
5. **事件顺序**：同一毫秒内多条事件用 `at` + 数组顺序；UI 排序稳定即可。
6. **发布绑定不要猜**：没有 bvid/平台不一致时不要自动绑定；显示原因。
7. **不要改云端**：`PublishedRecord`、`syncService`、Supabase schema 都不动；`publishRef` 只在本地 run。
8. **不要动门户**：当前门户 v5 未提交；R1/R2 只改工作台页面。
9. **不要提交/推送**：完成后给 `git diff --stat` 和截图；用户确认后再同步。
10. **中文/编码**：CSV 保留 BOM；事件摘要用中文 UTF-8；文件名 ASCII。
