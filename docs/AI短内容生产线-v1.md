# AI 短内容生产线 v1

> 适用：Creator Studio 成片任务 v2.1（R1 可追溯 + R2 发布闭环 + R3 多流水线/同组任务 + R4 素材库与版权 + R5 配音与字幕 + R6 成本/供应商/批量）  
> 对应 PRD：[PRD-成片任务-v1.md](PRD-成片任务-v1.md) · [PRD-成片任务-升级路线.md](PRD-成片任务-升级路线.md)  
> 定位：一份可执行、可复核、可交接的内容生产 SOP，不是「一键生成视频」的营销文案。

---

## 1. 一句话

把「脚本完成」到「可以交给发布同学」之间的工作，拆成五个有输入、有产出、有门禁的阶段；每一步都能查到依据、负责人和失败原因。

---

## 2. 五个阶段

> R3 起支持 3 条流水线：**B站长解说**、**抖音短切片**（五阶段），以及 **版本营销素材包**（脚本锁定 → 素材清单 → 导出交接包，不跑平台规则、无人工复核、不含完整分镜）。阶段轨、检查分组和导出文件都由流水线定义驱动；默认按脚本平台/版本推断。  
> R4 起素材库记录来源/授权/到期/允许平台；任务素材槽位可关联素材库，授权未记录、过期或平台不符会阻塞发布包。  
> R5 起长/短版使用流水线 v2（7 阶段）：素材之后增加配音与字幕；v1 旧任务仍按 5 阶段读取。

| # | 阶段 | 输入 | 关键动作 | 产出 | 门禁 |
|---|---|---|---|---|---|
| 1 | 脚本锁定 | 选题、脚本、分镜、平台检查 | 创建任务，保存不可变快照 | 任务快照 | 标题、钩子、分镜、时长为空则不能继续 |
| 2 | 发布前检查 | 任务快照、平台规则引擎 | 跑本地检查 + B站/抖音规则 | 检查清单（阻塞/提醒/通过） | 有阻塞项不能导出发布包 |
| 3 | 素材清单 | 分镜表 | 逐镜确认素材类型、状态、备注 | 素材清单 | 任一镜「待准备」不能导出 |
| 4 | 人工复核 | 检查结果、素材清单、版权确认 | 确认版权、写复核备注、标记通过 | 复核记录 | 版权未确认 / 有提醒但无备注不能通过 |
| 5 | 导出交接包 | 任务快照、检查、素材、复核 | 生成 ZIP，记录导出 | 发布交接包 | 只有「可导出」状态能生成发布包 |

> 草稿包随时可导出；发布包必须过门禁。草稿包会在 README 中标明 DRAFT 和未通过项。  
> 阶段工件：详情页右侧可单独下载 `script.md` / `shotlist.csv` / `assets.csv` / `checks.json` / `publish.md`，不要求先导出整包；内容来自当前 run 快照，下载不发网络请求。  
> 运行记录：创建、检查、素材、版权、复核、导出、归档、发布绑定都会追加事件（只记摘要，最多保留 200 条）。

## 3. 角色与职责

| 角色 | 负责 | 不负责 |
|---|---|---|
| 内容策划 / 运营 | 选题、脚本、分镜、平台适配、复核结论 | 不代替剪辑做最终成片 |
| 剪辑 / 设计 | 按素材清单准备镜头、封面、字幕（v1 外） | 不改脚本判断 |
| 运营负责人 | 版权/授权确认、发布前复核、异常升级 | 不跳过阻塞项 |
| 数据 / 复盘 | 发布后回填播放、互动、预测偏差 | 不把相关性自动解释成因果 |

一个人也可以完成全部角色，但**复核动作和版权确认必须留下记录**。

---

## 4. 平台口径

| 平台 | 建议时长 | 主要检查 |
|---|---|---|
| B站 | 3–10 分钟 | 播放分钟数口径、标题/封面、证据出处 |
| 抖音 | 1–3 分钟 | 完播率分档、标题/封面、时长拆条建议 |

平台规则来自 Creator Studio 的 `pure-rules-v1` 引擎，每条结论带 A/B/C 证据等级和出处。规则不是平台官方 KPI 承诺，发布后以真实数据为准。

---

## 5. 失败处理

| 情况 | 处理 | 谁处理 |
|---|---|---|
| 标题/钩子/分镜为空 | 修改源脚本，基于最新脚本新建任务 | 内容策划 |
| 时长不在平台区间 | 调整分镜或拆条；重新检查 | 内容策划 |
| 平台规则检查接口不可用 | 只能导出草稿包；恢复后重新检查 | 运营 / 工程 |
| 素材缺失 | 在素材清单标记「已准备」或「不需要」 | 剪辑 / 设计 |
| 版权未确认 | 勾选确认；保留确认人和时间 | 运营负责人 |
| 有提醒项 | 复核备注写明接受理由 | 复核人 |
| TTS worker 未运行 | 启动 worker 后重试；阶段保持阻塞，不伪造音频 | 运营 / 工程 |
| 字幕行宽/语速提醒 | 调整台词或镜头时长，重新生成字幕 | 内容策划 |
| 批量预检失败 | 点「重试失败项」；检查平台接口/网络后再次执行 | 任务 owner |
| 成本未记录 | 显示「未记录」，不补 0；以供应商账单为准 | 运营 |
| 导出后发现内容变更 | 重新检查、重新复核、重新导出 | 任务 owner |

原则：**没有依据就不写「通过」，没有确认就不写「可发布」。**

## 6. 一个完整示例

**输入**：一条 B站长版脚本，5 个分镜，总时长 425 秒；选题是《空洞骑士：丝之歌》首发实测。

1. 创建任务，锁定脚本快照。
2. 发布前检查：
   - 标题/钩子/分镜/时长通过
   - B站时长 7 分钟，落在 3–10 分钟区间
   - 封面文案为空 → 提醒
   - 选题评估有样本依据 → 通过
3. 素材清单：5 个镜头全部标记「已准备」，勾选版权确认。
4. 复核：填写「素材齐备、版权确认；发布后回填播放数据」，标记通过。
5. 导出发布包 ZIP：
   - `README.md`（READY）
   - `manifest.json`
   - `script.md`
   - `shotlist.csv`
   - `assets.csv`
   - `publish.md`
   - `checks.json`
   - `source-topic.json`

这个 ZIP 就是交给剪辑/发布同学的完整交接物；v1 不包含成片、配音和字幕。

## 7. 发布绑定与校准（R2）

1. 打开 run 详情 →「发布回填与校准」。
2. 选题还没有发布记录时，点「去记录发布」，跳到选题看板并自动打开记录发布弹窗；保存后发布记录仍只存在选题上。
3. 回到 run 详情，核对实际播放/互动、预测来源和偏差。平台不一致时只展示真实数据，不允许绑定。
4. 平台一致时点「绑定本次发布」：run 只记录本机 `publishRef`，并追加 `publish_bound` 事件；解绑/重新绑定同样留事件，不修改 `Topic.published`。
5. 同一发布记录已绑定到另一条任务时，必须二次确认才会转移绑定，不静默抢占。

口径：

- 实际数据来自 B站接口或人工填写；预测只用于校准，不是承诺。
- 没有数字化预测就不计算偏差，不补 0。
- 绑定发布不要求重新导出交接包；`manifest.json` 中的 run 会带上 `publishRef`。
- 发布仍由人工完成，系统不自动发布、不自动回填平台数据。

## 8. 流水线与同组任务（R3）

1. 创建任务时选择流水线；默认按脚本平台/版本推断（B站长版 → 长解说，抖音/短版 → 短切片）。营销素材包需手动选择。
2. **版本营销素材包**：脚本作为简报，只走「脚本锁定 → 素材清单 → 导出交接包」；不做平台规则 API、不进入人工复核，导出不含 `script.md/shotlist.csv`，`manifest.json` 会省略完整 `storyboards` 并标记 `storyboardsOmitted`。
3. **同组任务**：在同选题、另一平台的脚本版本上创建变体 run；两条任务共享 `campaignId`，但检查、素材、复核、导出包互不影响。
4. **组合包**：run 详情 →「同组任务」→「导出组合包」，每条任务放进 `runs/<platform>-<version>/`，顶层 `campaign.json` 记录流水线、状态和打包模式；未就绪任务使用 DRAFT 包，不伪造 READY。
5. 旧 run 没有 `pipelineId` 时按 `game-longform@1` 读取；manifest 会补上流水线信息。

## 9. 素材库与版权（R4）

1. **素材库**：收藏素材时记录来源（本地/图库/AI/原创）、授权类型（自有/已授权/CC/未记录）、授权链接、到期日、允许平台和校验值。
2. **槽位关联**：在任务素材清单点「从素材库选择」；系统按类型/标签/关键词给出建议，但不自动认定。关联后槽位显示素材库名称、来源、授权、到期和允许平台。
3. **授权门禁**：
   - 素材授权未记录 → `asset-rights-missing` 阻塞；
   - 授权已过期 → `asset-rights-expired` 阻塞；
   - 允许平台不含当前任务平台 → `asset-platform-blocked` 阻塞；
   - 已准备但未关联素材库 → `asset-unmatched` 提醒，不阻塞。
4. **未匹配豁免**：素材标记「不需要」时不产生 unmatched 提醒。
5. **导出**：`assets.csv` 增加来源、授权、到期、允许平台、素材 ID、素材名称；旧记录没有字段时显示「未记录」，不伪造授权。
6. **刷新**：重新检查、复核和导出前都会刷新素材授权快照；授权到期或素材元数据变化会更新门禁，必要时要求重新导出。
7. **同步**：只同步素材元数据，不把媒体文件放进云端或备份。

## 10. 配音与字幕（R5）

1. **启动 worker**：`powershell -File tools/tts-worker/start-tts-worker.ps1`。worker 只监听 127.0.0.1:3101，返回 MP3 与 TTS 句级时间戳。
2. **生成**：在 v2 任务的「配音与字幕」卡选择音色/语速/音调，点「生成配音与字幕」。音频 Blob 只存本机 IndexedDB 的 `runMedia`，不进备份/云同步。
3. **字幕**：按 TTS `SentenceBoundary` 生成 SRT；B站 18 字/行、抖音 12 字/行，最多 2 行。没有时间戳时用估算，并在检查里标明「估算时间」。
4. **检查**：
   - 配音未生成/失败 → 阻塞；
   - 配音时长与分镜总时长偏差过大 → 提醒；
   - 字幕未生成/失败 → 阻塞；
   - 行宽、阅读速度、时间戳来源、台词覆盖率 → 通过或提醒。
5. **复核/导出**：配音与字幕都就绪后才能复核；发布包 v2 包含 `voiceover.mp3`、`subtitles.srt`、`voice.json`、`subtitle.json`，README/manifest 标明媒体包含情况。
6. **Worker 不可用**：阶段保持阻塞，生成按钮禁用，不产生假音频；启动 worker 后重试。
7. **边界**：只做 TTS 句级时间戳，不做 Whisper 逐字对齐；媒体不跨设备同步，备份恢复后若音频缺失需要重新生成。

## 11. 成本、供应商与批量（R6）

1. **供应商口径**：任务详情「成本」→「供应商」查看能力、运行时、免费/付费、计价单位与 fallback。Edge TTS 与本地规则为免费；DeepSeek 为付费，单价按供应商账单，应用不猜价格。
2. **成本账本**：每次生成配音都会记录 provider、操作、字符数、估算/实际成本（Edge TTS 为 ¥0.00）；未记录的金额显示「未记录」，不补 0。实际账单以供应商为准。
3. **批量创建**：成片任务页「批量创建」→ 选一组脚本 → 设置并发（1–3）→ 创建 N 条独立 run。批量只创建与执行发布前检查，不自动准备素材/配音/复核。
4. **批量状态**：「已预检」只表示检查跑完，不代表可导出；逐条查看 run 状态与阻塞项。预检异常自动重试 2 次，失败项可在批量详情再次重试。
5. **备份 v4**：成本账本与批量任务随备份保存/恢复；旧 v1–v3 备份仍可读取；配音/视频媒体不进备份。
6. **边界**：批量是客户端执行，关闭页面会中断未完成项；真实付费供应商未接入 run 流水线，首次付费确认目前为口径说明，不会自动扣费。

## 12. 当前版本不做什么

- 不合成视频
- 不做 Whisper 对齐或逐字强制对齐
- 不自动发布，不自动绑定发布记录
- 不自动改写脚本或自动创建另一平台内容
- 不做自动版权判定，不自动抓取外部授权页
- 不自动调用付费供应商或自动扣费
- 不把媒体放进云端同步或本地备份
- 不把任务同步到云端（只在本机，进入本地备份）

R7 成片交接与质检已归类为后续升级方向，不在当前版本范围。当前版本的目标是把**判断、门禁、交接、回溯、成本**做扎实，而不是把项目做成另一个视频生成器。

## 13. 面试时怎么讲

> 我做的不是「AI 一键成片」，而是一条可审计的内容生产线：  
> 选题有样本依据，脚本有平台适配，生产前有阻塞/提醒门禁，素材和版权有确认记录，最后导出带 manifest 的交接包。  
> 这条线让内容运营从「凭感觉交付」变成「每一步都能被追问」。

对应岗位：

- 内容运营：SOP、产能、质量门禁、交接效率
- 创作者运营：素材清单、平台差异、复核机制
- 游戏营销：版本传播物料从 brief 到发布包的完整链路
