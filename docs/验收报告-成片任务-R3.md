## 1. 本次交付

### 流水线注册表

- 3 条流水线：`game-longform@1`（B站长解说）、`game-shortform@1`（抖音短切片）、`version-marketing-pack@1`（版本营销素材包）。
- 每条流水线定义：阶段、检查分组、导出文件分组。
- 创建任务时可选流水线；默认按脚本平台/版本推断（B站长版 → 长解说，抖音/短版 → 短切片）。
- 旧 run 没有 `pipelineId` 时回退 `game-longform@1`；manifest 会补上流水线 id/version。

### 流水线驱动的 UI 与导出

- **阶段轨**：长版/短版 5 阶段；营销包 3 阶段（脚本锁定 → 素材清单 → 导出交接包），不显示人工复核卡。
- **检查分组**：详情页按流水线显示「脚本与分镜 / 平台规则 / 选题依据 / 长版节奏」或「短版钩子」或「营销检查」等分组。
- **额外检查**：
  - 长版：章节节奏（少于 4 镜提醒）。
  - 短版：开场钩子（第一镜 > 5 秒提醒）、1–3 分钟节奏、竖屏交付提示；平台时长检查会带完播参考。
  - 营销包：目标/受众、卖点/简报、评估指标；不调用平台规则接口。
- **导出**：文件清单由流水线定义驱动。营销包只导出 `README.md / manifest.json / assets.csv / publish.md / checks.json / source-topic.json`，不含 `script.md/shotlist.csv`；manifest 标记 `storyboardsOmitted: true` 并清空 storyboards。
- **阶段工件**：营销包只显示 3 个相关工件（素材/检查/发布说明），长版/短版仍是 5 个。

### 同组任务与组合包

- run 详情新增「同组任务」卡；可从同选题、另一平台的脚本版本创建变体 run。
- 两条 run 共享 `campaignId`，新 run 记录 `variantOfRunId`；检查/素材/复核/导出包互不影响。
- 「导出组合包」生成：
  - `runs/bilibili-long/...`、`runs/douyin-short/...` 各自独立目录；
  - 顶层 `campaign.json` 记录流水线、状态、打包模式和发布绑定；
  - 未就绪任务用 DRAFT 包，不伪造 READY；
  - 组合包导出会写入每条任务的运行记录（“导出组合包”）。
- 归档一条同组任务不会改变另一条任务的状态。

### 数据与兼容

- `ProductionRun` 新增可选字段：`pipelineId`、`pipelineVersion`、`campaignId`、`variantOfRunId`。
- **未升 Dexie 版本**；备份仍为 v3，校验支持新字段和 `pipeline` 检查分类。
- 不修改云端表结构；campaign 由 run 字段聚合，不建表。

## 4. 已知限制

- 没有独立的 `/campaigns/:id` 页面；同组任务在 run 详情卡中展示（PRD 允许两种方案之一）。
- campaign 由 run 字段聚合，不建表；删除全部同组 run 后 campaign 不再存在。
- 「创建另一平台任务」只列出同选题、另一平台的脚本版本，不自动改写脚本。
- 营销素材包当前以所选脚本作为简报来源，**未直接挂接 `GameMarketingBrief`**；这是本期实现边界。
- 组合包中的非就绪任务使用 DRAFT，不强制要求所有任务先通过复核。
- 运行数据与 campaign 仍只在本机，不参与云同步；R4–R7 未开工。
