# Creator Studio 升级报告 · 最新版 vs 旧版

> 日期：2026-10-21  
> 对比对象：旧版（服务器当前部署） vs 最新版（当前本地工作区）  
> 状态：本地升级完成，**未提交、未推送、未部署**；`server/public` 未覆盖  
> 说明：本文为内部升级说明，**不进入网站页面**；网站不展示版本路线或后续规划。

---

## 一页摘要

旧版（2026-10-17 构建，入口 `index-Cn44VUme.js`）是一个以**选题、脚本、平台适配、报告、实验**为主的内容工作台；它没有 `/runs` 成片任务模块，也没有素材授权、配音字幕、批量/成本这些生产执行能力。

最新版（`index-ulko5muE.js`）在保留原有页面的基础上，补上了一条完整的**可追溯成片生产线**：

> 选题评估 → 分镜脚本 → 平台适配 → 成片任务（预检 / 素材授权 / 配音字幕 / 复核）→ 阶段工件或媒体包 → 发布回填与校准 → 复盘实验

这轮升级的重点不是“再加一个页面”，而是把“脚本完成之后到发布之后”的记录、门禁和回溯补齐，让内容运营从“策划工具”变成**可交付、可对账的生产系统**。门户页与关于页也按实际能力重写，分享图和 SEO 文案同步更新。

## 2. 升级内容

### 2.1 从“内容策划”到“可交付的生产线”

旧版的核心是“判断与策划”：选题评估、脚本、平台规则、报告。它回答了“做什么、怎么写、平台怎么建议”，但没有回答：

- 这份脚本有没有变成可交付的制作包？
- 素材齐不齐、版权/授权能不能核验？
- 配音、字幕有没有生成，质量如何？
- 谁在什么时候检查、改素材、复核、导出？
- 发布后真实数据能不能回到这条任务上？

最新版新增 `/runs` 成片任务主线，把这些断点接起来：

- **任务快照**：创建任务时锁定脚本、选题、平台检查，源脚本后续修改不会自动污染任务。
- **发布前检查**：标题、钩子、分镜、时长、平台规则、选题依据、素材、版权统一进入阻塞/提醒/通过。
- **素材与版权**：逐镜确认，素材库关联，授权/到期/平台范围校验。
- **配音与字幕**：本地 TTS 生成音频、句级时间戳字幕，按平台预设检查行宽/语速/覆盖率。
- **人工复核**：复核人、备注、提醒项说明；未通过不能导出发布包。
- **交接包**：阶段工件可单独下载；发布包/媒体包带 manifest 与 README。
- **发布校准**：绑定真实发布记录，显示播放/互动、预测与实际偏差。
- **运行记录**：上述动作全部追加事件，最多保留 200 条，刷新/备份恢复后仍在。

**原因**：旧版的生产判断停留在“文档/页面状态”，没有形成可交接、可追责的工件。真实内容运营的成本往往不在“想选题”，而在“做完之后发现素材缺、授权不明、版本不对、发布数据对不上”。这轮升级把这些问题前置成门禁。

### 2.2 可追溯：阶段工件 + 运行事件

- 5 个阶段工件：`script.md`、`shotlist.csv`、`assets.csv`、`checks.json`、`publish.md`，阻塞/草稿状态也可单独下载。
- 运行事件：创建、检查、素材、版权、复核、导出、归档、备注、发布绑定/解绑。
- 事件只记摘要，不写完整脚本/台词；最多 200 条，超出保留最近记录。
- 导出包 v2 增加 `voiceover.mp3`、`subtitles.srt`、`voice.json`、`subtitle.json`。

**原因**：旧版只能看到“当前状态”，看不到“为什么变成这个状态”。阶段工件解决“单点交付”，事件时间线解决“过程可追问”。这是审计型内容团队最需要的部分，也让作品集叙事从“我做了页面”变成“我设计了可追溯流程”。

### 2.3 发布闭环：任务级绑定与校准

- 从 run 详情进入「发布回填与校准」：
  - 有发布记录：显示真实播放/点赞/投币/收藏/分享/评论、发布时间、BVID、取数时间、来源；
  - 显示预测值、预测来源（AI/人工/历史目标）与偏差；
  - 无发布记录：空状态 + 「去记录发布」深链；
  - 平台不一致：只展示数据，禁止绑定；
  - 无数字化预测：不计算偏差，不补 0。
- 绑定 `run.publishRef`，只在本地；解绑/重新绑定留事件，不修改 `Topic.published`。
- `/?publish=<topicId>` 深链会自动打开发布弹窗。

**原因**：旧版有选题级发布回填，但“这条 run 对应哪次发布、预测偏差多少”没有落到任务上。任务级绑定让复盘能回到具体制作决策，而不是只看选题总量。

### 2.4 流水线与同组任务

- 3 条流水线：B站长解说、抖音短切片、版本营销素材包。
- 流水线驱动阶段、检查分组与导出文件；不是所有任务都套同一条五阶段模板。
- 营销素材包：3 阶段、不跑平台规则、无人工复核、不含完整分镜，manifest 省略 storyboards。
- 同组任务：同一选题的 B站/抖音版本成组创建，检查/素材/复核互不影响；组合包按 run 目录归档并附 `campaign.json`。

**原因**：旧版只有一条隐式流水线。真实内容团队会同时做长视频、短视频切片、版本营销物料；如果都套同一套门禁和导出，要么过度检查，要么漏掉关键差异。流水线注册表把“差异”变成可配置的产品能力，而不是页面里写死的 if/else。

### 2.5 素材库与版权

- 素材新增：来源、授权类型、授权链接、到期日、允许平台、校验值、使用次数。
- 任务槽位可关联素材库，保存授权快照；建议匹配只做类型/标签/关键词，不自动认定。
- 授权未记录、过期、平台不允许 → 阻塞发布包；已准备未关联 → 提醒；标记“不需要” → 不阻塞。
- `assets.csv` 增加来源、授权、到期、允许平台、素材 ID、素材名称。

**原因**：旧版素材库只是“链接收藏夹”，无法回答“这个素材能不能在 B站/抖音用、授权到什么时候”。版权/授权是最容易在发布前才暴露的风险，必须进入门禁和导出清单。

### 2.6 配音与字幕

- 本地 Edge TTS worker：返回 MP3 与 TTS 句级时间戳；音频只存本机 IndexedDB（`runMedia`），不进备份/云同步。
- 字幕按 B站/抖音预设生成 SRT，检查行宽、阅读速度、时间戳来源与台词覆盖率。
- worker 不可用时配音阶段阻塞、生成按钮禁用，**不生成假音频**。
- 媒体包 v2 带音频/字幕/JSON；组合包也按任务目录带入。

**原因**：旧版没有音频/字幕，交接包只到“脚本+素材清单”。真实成片流程里，配音和字幕是剪辑前必须确定的输入；同时它们涉及媒体文件，必须和“只同步元数据”的云端边界分开。

### 2.7 成本、供应商与批量

- 供应商注册表：Edge TTS、本地规则、B站公开接口、DeepSeek、人工复核，标注能力、运行时、免费/付费、计价口径。
- 成本账本：每次配音记录 provider、字符数、实际/估算成本；未记录金额显示“未记录”，不补 0。
- 批量创建：多选脚本 → N 条独立 run → 并发 1–3 预检 → 失败自动重试 2 次 → 失败项可再次重试。
- 批量详情：逐条预检状态、run 阻塞、错误、跳转链接；成本汇总。
- 备份 v4：包含 runs / costs / batches；旧 v1–v3 备份仍可读。

**原因**：旧版无法回答“批量做 5 条要多久、哪条失败、花了多少钱”。当内容生产从单条变成批量，成本与失败可观测性比“再做一个表单”更重要。本地先做 estimate/actual 账本，不伪造未拿到的供应商账单。

### 2.8 门户、关于与分享

- 门户：五道工序改为按实际生产顺序，配图换成成片任务、素材授权、配音字幕、发布校准、同组任务、批量成本；数据依据更新为 8 个品类 / 64 个带来源数字 / 3 条流水线 / 5 个阶段工件。
- 关于：推荐路线改为与生产顺序一致；素材库/分析报告/营销简报移到“跨流程入口”；技术栈补充 Dexie v10、可选本地 TTS worker。
- 网站不展示版本路线/R1–R6/R7；后续规划只留在内部文档。
- SEO/OG：description、OG 描述、首屏 LCP 预加载从旧 dashboard 换成成片任务；重新生成 1200×630 分享图。

**原因**：旧版门户/关于页仍描述“选题→复盘”的旧能力，配图与文案落后于实际产品；对于作品集来说，第一屏如果还在讲旧功能，会直接削弱升级的可信度。网站同时不应暴露内部版本规划，避免让访客/面试官看到未完成的路线。

### 2.9 工程与数据边界

- Dexie：v7 的 runs 保留；v9 新增本机 `runMedia`；v10 新增 `runCosts` / `runBatches`。
- 本地备份 v4；旧 v1–v3 兼容；媒体不进备份/云同步。
- v1 任务仍按 5 阶段读取；新增长/短版任务默认 v2（7 阶段），旧任务不会突然要求配音/字幕。
- 云端仍只同步选题/脚本/素材元数据；runs/costs/batches/media 只在本机。
- 验收：`runs-e2e` 79/79、`runs-r5-e2e` 13/13、`runs-r6-e2e` 10/10、`run-preflight-test` 43/43、`panel-e2e` 25/25、`smoke-test` 33/33；tsc 0、oxlint 0 error、build 通过。

**原因**：这轮升级增加了媒体、成本、批量等新数据。如果直接上云或进备份，会带来体积、隐私和迁移风险。保持“运行数据/媒体本地，云端只同步元数据”的既有原则，升级才可控。

## 3. 为什么这样升级（决策理由）

### 3.1 旧版的问题不是“页面不够多”，而是“生产链断在脚本之后”

旧版已经能回答“做什么、怎么写、平台怎么说、数据怎么样”，但脚本完成后的执行、交接、发布对账没有系统承接。新增 `/runs` 不是增加一个入口，而是补齐“从脚本到发布”的缺失段。

### 3.2 先做可追溯，再做自动化

没有阶段工件、事件、授权和门禁，直接做“一键生成/批量生产”只会放大不可控。顺序是：

1. 先让每一步有记录、可下载、可复核；
2. 再让多条流水线/同组任务可组织；
3. 再让配音、字幕、批量、成本进入门禁；
4. 最后才考虑成片渲染/交接。

### 3.3 数据诚实优先

这轮升级反复选择“不伪造”：

- 没有发布记录 → 空状态，不显示 0；
- 没有数字化预测 → 不算偏差，不补 0；
- 没有 TTS worker → 阶段阻塞，不生成假音频；
- 没有授权记录 → 阻塞发布包，不推断“应该没问题”；
- 没有供应商账单 → 显示“未记录/按供应商账单”，不猜单价。

这也是产品与普通“AI 内容工具”的差异：**能解释、能复核、能承认不知道**。

### 3.4 本地优先，媒体与运行数据不出本机

选题/脚本可以云同步，但成片任务、授权快照、音频、成本、批量结果默认只在本机。原因是：

- 媒体文件体积大，云同步成本高；
- 授权/成本/发布绑定属于敏感运营数据；
- 本地优先能让作品集在没有云端依赖时也能完整演示；
- 备份仍可导出，但媒体单独处理。

### 3.5 网站叙事与产品能力对齐

旧版门户/关于页仍然以“选题→复盘”的旧叙事为主，甚至关于页写的是“770 条公开样本”。实际产品已经补上成片任务、素材版权、配音字幕、批量成本。升级网站不是美化，而是让访客第一眼看到真实产品能力，同时不展示内部版本规划。

## 4. 兼容性与上线影响

| 项 | 影响 |
|---|---|
| 旧 run | 仍按 v1 五阶段读取；不会突然要求配音/字幕 |
| 新 run | 长/短版默认 v2 七阶段；营销包为三阶段 |
| 本地数据 | Dexie 自动升级到 v10；runs 表结构不变 |
| 备份 | v4；旧 v1–v3 可读取并恢复；媒体不进备份 |
| 云端 | 不改 Supabase 表结构；runs/costs/batches/media 不同步 |
| 现有页面 | 选题、脚本、素材、报告、实验、简报、设置保留 |
| 旧版静态资源 | `server/public` 未覆盖；服务器仍保留旧构建 |
| TTS | 公共访客没有本地 worker 时，配音阶段会阻塞；这是预期降级，不是造假 |

**上线前需要确认**：

1. 是否把“成片任务”作为公开作品集的主入口；如果公开部署，需要说明配音需要本地 worker，或提供演示媒体/只读模式。
2. 是否保留演示任务（v1）作为无 worker 的完整可走通示例；当前演示任务固定 v1，不需要 TTS。
3. 是否接受本地备份 v4 与 Dexie v10 的升级；旧浏览器数据会自动迁移。
4. `server/public` 替换需要按项目流程构建/备份，本轮**没有执行**。

## 6. 后续方向

### 6.1 第一优先：把当前版本安全上线

当前升级仍只在本机。建议顺序：

1. 确认门户/关于文案与配图；
2. 确认是否公开配音入口，以及无 worker 时的降级说明；
3. 备份本地数据，执行构建与预览验收；
4. 再按项目部署流程替换 `server/public`（本轮未执行）。

### 6.2 R7：成片交接与质检（后续升级方向，不在当前版本）

R7 的目标是让“交接包”继续走到剪映/EDL/FCPXML 或本地 FFmpeg 合成，并做时长/画幅/编码/音量/黑帧/静音/字幕质量检查。当前不做，原因是：

- 本机没有 FFmpeg/ffprobe；
- 本机没有安装剪映，无法验证“能在剪映打开”；
- 素材库目前只存链接/授权元数据，没有本地视频/图片文件，无法组成真实时间线；
- 在这种条件下硬做，只能生成空引用或伪造 QA 报告。

合理的 R7 路径：

1. 先补“本地素材文件导入/固定路径”（R4 延伸）；
2. 安装 FFmpeg worker，做 probe / 合成 / 抽帧 / 音量与静音检查；
3. 导出 EDL/FCPXML/剪映草稿，人工在剪映验证；
4. 再把 `delivery_report.json` 接入发布门禁。

### 6.3 其他可验证的增强

- 字幕逐词/Whisper 对齐（当前是 TTS 句级时间戳）；
- 供应商实际 token/账单同步（当前只记录 Edge TTS 的 0 元成本，DeepSeek 按账单口径）；
- 素材库本地文件与版本管理（当前只有链接与授权元数据）；
- 批量任务的后台/断点续跑（当前是客户端执行，关闭页面会中断）。

### 6.4 网站与文档边界

网站只展示**已实现且可演示**的能力，不展示 R1–R6/R7 版本规划；内部路线仍保留在 `docs/PRD-成片任务-升级路线.md`。这样访客/面试官看到的是产品，而不是未完成的计划。

## 7. 结论

旧版是一个成熟的“内容策划 + 数据”工作台；最新版本把它向前后各延伸了一步：

- 向后：从脚本延伸到成片任务、素材版权、配音字幕、复核与交接包；
- 向前：从选题级发布回填延伸到任务级发布绑定与预测校准；
- 横向：用流水线/同组任务/批量/成本支撑多平台、多批次生产；
- 叙事：门户与关于页按真实能力重写，不再展示内部版本规划。

这不是“又加了很多功能”，而是把内容运营最容易被忽略的**执行、门禁、回溯、成本**补成了同一条可查的链路。当前本地验收通过，尚未部署；上线前需要先确认 TTS worker 的公开降级策略与 `server/public` 的替换流程。
